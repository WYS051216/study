# Linux 底层进阶笔记：多进程理论核心

## 1.1 引入多进程的目的

1. **并发执行**：实现多任务并发执行的核心途径。
2. **协作提升效率**：可以实现数据在多个进程之间进行通信，共同处理整个程序的相关数据，充分榨干 CPU 性能。

## 1.2 多进程相关概念

1. **定义**：进程是程序的一次执行过程，具有动态性和生命周期（包含创建态、执行态、就绪态、挂起态、死亡态）。
2. **资源分配**：**进程是计算机系统资源分配的基本单位**。系统会给每个进程分配 0~4G 的虚拟内存（32位系统下）。
   * **用户空间 (0~3G)**：多个进程的用户空间是**相互独立**的，互不干扰。
   * **内核空间 (3~4G)**：所有进程的内核空间是**相互共享**的。
3. **调度机制**：时间片轮转（Round-Robin）与上下文切换（Context Switch）机制。
4. **并发 (Concurrency) vs 并行 (Parallelism)**：
   * **并发**：针对单核 CPU。宏观上多个任务“同时”执行，微观上是通过调度机制将时间片切分，同一时刻只有一个任务在被 CPU 处理（交替执行）。
   * **并行**：针对多核 CPU。同一时刻，多个 CPU 核心真正意义上同时处理多个不同的任务（物理上的同时执行）。

---

## 1.3 进程的内存管理（核心补充）

当一个程序被加载到内存中变成进程时，它的 0~3G 用户空间会被系统进行极其严格的区域划分（从低地址到高地址依次为）：

1. **代码段 (Text Segment / 只读区)**：存放程序执行的机器指令（二进制代码）和只读常量。该区域是只读的，防止程序意外修改自己的指令。
2. **数据段 (Data Segment / 静态区)**：
   * **.data 段**：存放**已初始化**的全局变量和静态变量。
   * **.bss 段**：存放**未初始化**（或初始化为 0）的全局变量和静态变量。
3. **堆区 (Heap)**：用于程序运行时的动态内存分配（如 C 中的 `malloc`，C++ 中的 `new`）。由程序员手动申请和释放，**内存地址自下而上（向高地址）增长**。
4. **栈区 (Stack)**：存放局部变量、函数参数、返回值以及函数调用时的上下文信息。由编译器自动分配和释放，**内存地址自上而下（向低地址）增长**。

---

## 1.4 进程和程序的区别


| 维度         | 程序 (Program)                     | 进程 (Process)                             |
| :----------- | :--------------------------------- | :----------------------------------------- |
| **状态**     | 静态的 (Static)                    | 动态的 (Dynamic)                           |
| **存储位置** | 存储在磁盘等外部介质上的二进制文件 | 加载在内存中，拥有系统分配的 0~4G 虚拟内存 |
| **生命周期** | 永久存在（除非被手动删除）         | 有完整的生命周期（创建、运行、消亡）       |

---

## 1.5 进程的种类

一共有三种核心类型：

1. **交互进程 (Interactive Process)**：由 Shell 控制，可以直接和用户进行交互反馈（如终端、文本编辑器 `vim`）。
2. **批处理进程 (Batch Process)**：系统内部维护了一个队列，放入该队列的进程会被统一、按顺序后台处理（如 `g++` 编译器的一步到位编译、数据库的定时备份脚本）。
3. **守护进程 (Daemon Process)**：脱离终端而存在，随系统启动而运行，随系统关闭而终止，一直在后台默默提供服务（如网络服务 `sshd`、系统日志服务）。

---

## 1.6 进程 PID 的概念

* **PID (Process ID)**：进程号。一个大于等于 0 的整数，是进程在系统中的唯一标识，绝不重复。
* **PPID (Parent Process ID)**：父进程号。Linux 中几乎每个进程都是由另一个进程（父进程）拷贝资源（`fork`）衍生出来的。
* **💡 避坑细节**：在 Linux 系统中，存放当前所有运行进程运行状态的目录是 **`/proc`** 目录（而不是根目录 `/`）。里面那些以纯数字命名的文件夹，就是各个进程的 PID。

---

## 1.7 特殊进程与异常进程

### 三大特殊进程

1. **0 号进程 (idle / swapper)**：Linux 系统启动后运行的**第一个进程**（空闲进程）。当没有其他进程需要运行时就运行它。它是 1 号和 2 号进程的“祖师爷”。
2. **1 号进程 (init / systemd)**：由 0 号进程创建。负责完成硬件的必要初始化工作，同时它是一个“大善人”，专门负责**收养所有的孤儿进程**。
3. **2 号进程 (kthreadd)**：由 0 号进程创建。也称调度进程，专门负责内核线程的任务调度。

### 两种异常进程状态（重点关注）

1. **孤儿进程 (Orphan Process)**：当前进程还在运行，但它的**父进程已经先退出了**。它会被 1 号进程收养，属于正常现象，无害。
2. **僵尸进程 (Zombie Process)**：当前进程已经运行结束退出了，但它的**父进程没有调用 `wait/waitpid` 为其回收资源**（如释放 PID 和 PCB 控制块）。
   * *危害：僵尸进程不占内存，但会持续占用系统的 PID 资源。如果不处理，会导致系统无法创建新进程。*

## 1.8 进程操作指令与信号

### 1. 常用监控指令

* **`ps`**：查看当前运行进程的静态快照。
  * `-ef`：显示进程父子关系（UID, PID, PPID, STIME, CMD, **TTY为 `?` 表示不依赖终端**）。
  * `-ajx`：显示进程状态（PGID 进程组ID, SID 会话组ID, STAT 进程状态）。
  * `-aux`：查看资源占用（%CPU, %MEM）。
* **`top`**：动态、实时查看系统的进程状态和资源占用（相当于 Windows 任务管理器）。
* **`pidof 进程名`**：精准提取某个正在运行的程序的 PID。

### 2. `kill` 指令与核心信号

* **语法**：`kill -信号编号 PID` （查阅信号可通过 `kill -l`）。
* **核心信号表（共 64 个，前 31 个为不可靠标准信号）**：
  * `SIGHUP (1)`：终端关闭时发送给所有挂载进程，默认结束进程。
  * `SIGINT (2)`：中断信号，用户在终端键入 **`Ctrl + C`** 时发出。
  * `SIGQUIT (3)`：退出信号，用户键入 **`Ctrl + \`** 时发出，通常会产生 Core Dump 核心转储文件。
  * `SIGKILL (9)`：**最强击杀信号！强制杀死进程。**
  * `SIGSEGV (11)`：段错误信号。当指针越界、非法访问内存时，系统内核发出的击杀信号。
  * `SIGPIPE (13)`：管道破裂。向一个没有读端的管道写数据时触发。
  * `SIGALRM (14)`：定时器超时。
  * `SIGTSTP (20)`：终端挂起信号。用户键入 **`Ctrl + Z`** 时发出，进程进入暂停态。
  * `SIGUSR1 (10) / SIGUSR2 (12)`：留给程序员自定义操作的保留信号。
* **⚠️ 两大特权信号**：**`SIGKILL (9)`** 和 **`SIGSTOP (19)`**。这俩信号极其霸道，**既不能被进程捕获，也不能被忽略**，操作系统对它们有绝对执行权。

## 1.9 进程状态的切换 (`STAT` 标志解析)

通过 `ps -aux` 或 `ps -ajx` 可以看到 `STAT` 列，包含“主状态”和“附加态”：

### 1. 进程主状态（大写字母）

* **`R` (Running / Runnable)**：运行态或就绪态。进程正在 CPU 上跑，或者在就绪队列里排队等 CPU。
* **`S` (Interruptible Sleep)**：可中断的睡眠态。进程在等待某个事件（如等待键盘输入、等待网络数据），**随时可以被信号唤醒**。
* **`D` (Uninterruptible Sleep)**：不可中断的睡眠态。通常是在等待磁盘 I/O 等底层硬件操作。**在这个状态下，连 `kill -9` 都杀不死它**，只能等 I/O 结束或重启计算机。
* **`T` (Stopped)**：暂停态。通常是收到 `SIGSTOP` 或 `SIGTSTP` (`Ctrl+Z`) 信号后停下来。
* **`t` (Tracing stop)**：追踪暂停态。比如你用 GDB 调试代码，打了个断点，程序停在断点处就是这个状态。
* **`X` (Dead)**：死亡态。进程即将被销毁（极其短暂，几乎抓不到）。
* **`Z` (Zombie)**：僵尸态。进程已死，但父进程还没来收尸。

### 2. 附加状态修饰符（小写字母或符号）

* **`<`**：高优先级进程（获得 CPU 资源的概率更高）。
* **`N`**：低优先级进程。
* **`L` (Locked)**：该进程有页面被锁定在内存中（防止被系统交换到磁盘 Swap 区，常用于对实时性要求极高的程序）。
* **`s` (Session leader)**：会话组长（表示它下面还有很多小弟进程，比如你打开的 bash 终端本身就是一个 `s`）。
* **`l` (Multi-threaded)**：多线程进程（表示这个进程内部包含了多个子线程）。
* **`+`**：前台进程（比如正在霸占你终端输出的进程，如果没有 `+`，说明它在后台默默运行）。

### 3. 进程主要状态的转换（核心状态机）

在 Linux 的底层实现中，**“就绪态”和“运行态”都被统一标记为 `R` (Running)**。但为了彻底理解进程的流转，我们在逻辑上必须将它们分开推演。以下是核心的状态转换路径：

#### ① 就绪态 (Ready) ⇌ 执行态 (Running)

这是系统中最频繁发生的状态切换，完全由**操作系统的调度器（Scheduler）**掌控。

* **就绪 ➔ 执行（被调度）**：进程在就绪队列中排队，当调度器发现 CPU 空闲，且轮到该进程时，会为其分配“时间片”，进程开始在 CPU 上真正执行代码。
* **执行 ➔ 就绪（被剥夺）**：
  * **时间片耗尽**：进程分配到的 CPU 时间用完了，即使代码没跑完，也必须乖乖让出 CPU，回到就绪队列末尾重新排队。
  * **被抢占**：突然来了一个优先级更高（或实时性要求更高）的进程，当前进程会被系统强行踢下 CPU，变回就绪态。

#### ② 执行态 (Running) ➔ 睡眠/阻塞态 (Sleep: `S` 或 `D`)

当进程在执行过程中，遇到了 **“自己无法立刻解决，必须等待外部条件”** 的情况时，就会主动让出 CPU，进入睡眠。

* **等待 I/O**：比如进程调用了 `read()` 读文件，或者 `recv()` 等待网络数据，由于磁盘/网络速度远慢于 CPU，进程会进入休眠等待（通常是 `S` 态，如果是极底层的硬件交互则是 `D` 态）。
* **等待锁/资源**：多进程竞争共享资源时，如果没有抢到互斥锁，进程也会进入休眠等待。

#### ③ 睡眠/阻塞态 (Sleep: `S` 或 `D`) ➔ 就绪态 (Ready)

* **条件满足（被唤醒）**：当磁盘数据读取完毕、网络数据包到达，或者别人释放了互斥锁，系统内核会立刻产生一个中断，将该进程从休眠队列中唤醒，重新放入**就绪队列**（注意：是回到就绪态排队，而不是立刻获得 CPU 执行）。
* **收到信号（仅针对 `S` 态）**：如果进程处于 `S`（可中断休眠），此时收到类似 `SIGINT` (Ctrl+C) 的信号，进程会被强行唤醒去处理信号。

#### ④ 执行态 (Running) ⇌ 暂停态 (Stopped: `T`)

* **执行 ➔ 暂停**：进程在运行中，收到了特殊的暂停信号（如 `SIGSTOP` 或 `SIGTSTP`，即用户按下 `Ctrl+Z`）。进程会被彻底冻结，挂在后台不动。
* **暂停 ➔ 就绪**：只有当该进程收到**恢复信号 `SIGCONT`** 时，它才会解冻，重新进入就绪队列等待 CPU 分配。

#### ⑤ 执行态 (Running) ➔ 僵尸态 (Zombie: `Z`) ➔ 死亡态 (Dead: `X`)

* **执行 ➔ 僵尸（自然死亡或被杀）**：进程的代码执行到了最后的 `return 0` 或 `exit()`，或者被 `kill -9` 信号击杀。此时进程的主体内存已经被系统回收，但为了给父进程留个“遗言”（退出状态码），它的 PCB（进程控制块）依然保留在系统中，变成 `Z` 态。
* **僵尸 ➔ 死亡（入土为安）**：父进程调用了 `wait()` 或 `waitpid()` 函数，成功读取了子进程的退出状态码，操作系统随即销毁该进程的最后一点残留（PCB），进程彻底灰飞烟灭（短暂经过 `X` 态后消失）。
