# 💻 C++ 核心机制：constexpr 关键字笔记

## 1. 核心概念
`constexpr` 的全称是 **constant expression（常量表达式）**。
它的核心作用是：**强制要求编译器在“编译期间”计算出结果**，而不是等到程序“运行期间”再去消耗 CPU 计算。

---

## 2. 核心用法

**① constexpr 变量（严格的编译期常量）**
* 等号右边的值必须在编译阶段就能确定。
* 极度安全，常用于定义数组大小、模板参数或 `switch-case` 标签。
```cpp
constexpr int c = 30; // ✅ 严格的编译期常量
int arr[c];           // ✅ 合法，数组大小在编译时已确定

// int n; cin >> n;
// constexpr int d = n; // ❌ 报错：n 是运行期用户输入的，编译期算不出来
```

**② constexpr 函数（可提前执行的函数）**
* **智能分发**：如果传入的参数是编译期常量，函数会在编译时直接算出结果并替换到代码中（没有函数调用开销）；如果传入的是运行期变量，它会自动“退化”为普通的函数在运行时执行。
```cpp
constexpr int square(int x) { return x * x; }

constexpr int res1 = square(5); // ✅ 魔法：编译期直接算出 25，等价于 int res1 = 25;
int n = 4;
int res2 = square(n);           // ✅ 退化：按普通函数在运行期计算 4 * 4
```

---

## 3. ⚠️ 核心考点：const vs constexpr

这是极易混淆的面试高频题，记住核心区别：
* **`const` = 只读 (Read-only)**：意思是“不要修改我”。但这个值到底什么时候算出来？不一定。它可能是编译时确定的，也可能是运行时才生成的（比如接收一个 `rand()` 随机数）。
* **`constexpr` = 编译期可知 (Known at compile-time)**：极度严格！它不仅要求“只读”，还强制要求“必须在编译阶段就算出具体的值”。

---

## 4. 引入的好处与优势
* **极致性能优化**：将运行时的计算开销转移给编译器，实现零成本抽象（Zero-cost abstraction）。
* **替代宏定义**：完美替代无脑文本替换的 `#define MAX 100`，提供严格的类型检查，更安全易调试。
* **泛型基石**：在现代 C++（C++11 及以后）的模板元编程中，它是实现在编译期进行逻辑推导的绝对核心。
