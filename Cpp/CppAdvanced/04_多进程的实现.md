# 💻 Linux 多进程机制与核心 API 笔记

**【核心概念】进程的创建过程**
子进程是通过**拷贝父进程**得到的。新进程的创建直接拷贝父进程的资源，只需改变很少部分的数据，保留了父进程的大部分的数据信息。在 Linux 系统中，这个拷贝过程通过 `fork` 函数自动完成。

---

## 1. 进程的创建：`fork()`

### 📝 函数说明
* **头文件**：`#include <unistd.h>`
* **函数原型**：`pid_t fork(void);`
* **功能**：通过拷贝父进程得到一个子进程。
* **参数**：无。
* **返回值**：
  * **成功**：在父进程中得到一个子进程的 `pid`（大于 0 的真实进程号），在子进程中得到 `0`。
  * **失败**：返回 `-1` 并置位错误码。

### 💻 代码示例

**例 1：不关注返回值的案例**
```cpp
#include<unistd.h>
#include<stdio.h>
int main()
{
    printf("Hello World\n");
    fork();
    //这个函数的作用是：以当前进程为模板，瞬间在内存中克隆出一个一摸一样的子进程
    //最核心的机制：子进程不仅复制了父进程的变量和代码，还复制了父进程的“进度条”（程序计数器）
    //当克隆完成的那一瞬间，系统里就存在了两个一模一样的进程，他们此时此刻都站在fork()这一行的下面，准备往下执行，所以第二句printf会执行两次
    printf("Hello World  1111\n");
    while(1);
    return 0;
}
```

**例 2：关注返回值的情况**
```cpp
#include<unistd.h>
#include<stdio.h>
int main()
{
    pid_t pid = -1;
    pid = fork();
    //创建一个子进程，给父进程返回：子进程的真实的身份证号
    //给子进程返回：数字0
    //如果返回-1，说明系统出问题，克隆失败
    printf("pid = %d\n", pid);
    //对pid进行判断
    if(pid > 0)
    {
        //父进程要执行的代码
        printf("我是父进程\n");
    }
    else if(pid == 0)
    {
        //子进程要执行的代码
        printf("我是子进程\n");
    }
    else{
        perror("fork error");
        return -1;
    }
    return 0;
}
```

## 2. 父子进程号的获取：`getpid()` & `getppid()`

### 📝 函数说明
* **头文件**：`#include <sys/types.h>`, `#include <unistd.h>`

**① 获取自身 PID**
* **函数原型**：`pid_t getpid(void);`
* **功能**：获取当前进程的进程 ID 号。
* **返回值**：当前进程的进程 ID 号。

**② 获取父进程 PID**
* **函数原型**：`pid_t getppid(void);`
* **功能**：获取当前进程的父进程 PID 号。
* **返回值**：当前进程的父进程 PID。

### 💻 代码示例
```cpp
#include<unistd.h>
#include<stdio.h>
int main()
{
    pid_t pid = -1;
    //创建进程
    pid = fork();

    if(pid > 0)
    {
        //输出当前父进程的进程号，父进程的子进程进程号，父进程的父进程进程号
        printf("self pid = %d, child pid = %d, parent pid = %d\n", getpid(), pid, getppid());
    }else if(pid == 0)
    {
        //输出子进程的进程号，子进程的父进程进程号
        //ps:这里的getppid()正常情况下是等于上面父进程的getpid()，但是如果父进程跑的太快已经死掉了，这里就会打印出1(变成了孤儿进程)
        printf("self pid = %d, parent pid = %d\n", getpid(), getppid());
    }else
    {
        perror("fork error");
        return -1;
    }
    return 0;
}
```

## 3. 进程退出函数：`exit()` 与 `_exit()`

上述两个函数都可以完成进程的退出，**核心区别在于：退出进程时，是否刷新标准 IO 的缓冲区**。
* **刷新缓冲区的意义**：把憋在内存里还没发出去的数据，强制写到它们真正该去的地方（如屏幕或文件）。

### 📝 函数说明

**① `exit()`（属于 C 库函数）**
* **头文件**：`#include <stdlib.h>`
* **函数原型**：`void exit(int status);`
* **功能**：退出当前进程，**并刷新**当前进程打开的标准 IO 缓冲区。
* **参数**：进程退出时的状态，会将该值与 `0377` 进行位与运算后，返回给回收资源的进程。

**② `_exit()`（属于系统调用/内核函数）**
* **头文件**：`#include <unistd.h>`
* **函数原型**：`void _exit(int status);`
* **功能**：退出当前进程，**不刷新**当前进程打开的标准 IO 缓冲区。
* **参数**：同 `exit()`。

### 💻 代码示例
```cpp
#include <stdio.h>
#include <stdlib.h> // exit() 所在的头文件
#include <unistd.h> // _exit() 所在的头文件

int main() {
    // 故意打印一句没有换行符 '\n' 的话
    // 因为没有 '\n'，这句话会被死死憋在 1024 字节的行缓存里，不会上屏幕
    printf("Hello, I am stuck in the buffer...");

    // 使用exit(0)
    // 结果：程序结束时，"Hello..." 会被成功强制刷新到屏幕上！
    exit(0); 
    
    // 把上面那行注释掉，换成_exit(0)
    // 结果：程序瞬间结束，没有任何善后。
    // 你在屏幕上什么都看不到，那句 "Hello..." 随着内存的销毁，直接灰飞烟灭了。
    // _exit(0); 
}
```

## 4. 进程资源的回收：`wait()` & `waitpid()`

### 📝 函数说明
* **头文件**：`#include <sys/types.h>`, `#include <sys/wait.h>`

**① `wait()`（阻塞回收）**
* **函数原型**：`pid_t wait(int *status);`
* **功能**：阻塞回收任意一个子进程的资源。
* **参数**：接收子进程退出时的状态（与 `0377` 位与后的结果）。如果不愿意接收，可以填 `NULL`。
* **返回值**：成功返回回收资源的那个子进程的 PID 号；失败返回 `-1` 并置位错误码。

**② `waitpid()`（可阻塞/非阻塞回收）**
* **函数原型**：`pid_t waitpid(pid_t pid, int *status, int options);`
* **功能**：可以阻塞也可以非阻塞回收指定进程的资源。
* **参数 1 (`pid`)**：
  * `> 0`：表示回收指定的进程号，进程号为 `pid`。
  * `= 0`：表示回收当前进程所在进程组中的任意一个子进程。
  * `= -1`：表示回收任意一个子进程。
  * `< -1`：表示回收指定进程组中的任意一个子进程，进程组 ID 为给定的 `pid` 的绝对值。
* **参数 2 (`status`)**：接收子进程退出时的状态，不需要可填 `NULL`。
* **参数 3 (`options`)**：控制是否阻塞。
  * `0`：表示阻塞等待。*(注：`waitpid(-1, &status, 0)` 等价于 `wait(&status)`)*
  * `WNOHANG`：表示非阻塞。
* **返回值**：
  * `> 0`：返回成功回收的子进程 PID 号。
  * `= 0`：表示本次没有回收到子进程。
  * `= -1`：表示出错并置位错误码。

### 💻 代码示例与生命周期解析
```cpp
#include<unistd.h>
#include<stdio.h>
#include<sys/types.h>
#include<sys/wait.h>
#include<stdlib.h>
int main()
{
    pid_t pid = -1;
    //创建进程
    pid = fork();

    if(pid > 0)
    {
        //输出当前进程号，子进程号，父进程号
        printf("self pid = %d, child pid = %d, parent pid = %d\n", getpid(), pid, getppid());
        //sleep(8);
        //wait(NULL);     //只有回收了子进程资源后，父进程才会继续向后执行  
        waitpid(-1, NULL, WNOHANG);
        printf("子进程资源已经回收\n");
    }else if(pid == 0)
    {
        //输出当前进程号，父进程进程号
        printf("self pid = %d, parent pid = %d\n", getpid(), getppid());
        printf("11111111111");
        sleep(3);
        exit(EXIT_SUCCESS);
    }else
    {
        perror("fork error");
        return -1;
    }
    while(1);
    return 0;
}
```

> **💡 综合案例全流程解析：**
> 这段代码完整演示了多进程生命周期中的核心机制：`fork()` 将程序一分为二后，子进程在第 3 秒率先苏醒，利用 `exit()` 强制刷新缓冲区的特性输出了之前被“憋住”的数字，随后结束生命；由于此时父进程仍在长达 8 秒的深度休眠中未能及时“收尸”，导致死去的子进程被迫当了 5 秒钟等待回收的“**僵尸进程**”，直到第 8 秒父进程终于苏醒，并立刻通过 `wait()` 函数成功清理了子进程的残留资源，最终完成了整个程序的闭环与安全退出。


练习：使用多进程完成两个文件的拷贝工作，父进程拷贝前一半的内容，子进程拷贝后一半的内容，父进程要回收子进程的资源
```cpp
#include<sys/types.h>
#include<sys/wait.h>
#include<unistd.h>
#include<stdio.h>
#include<stdlib.h>
#include<fcntl.h>

//定义求文件大小的函数
int get_file_size(const char *srcfile, const char *dstfile)
{
    //以只读的形式打开源文件
    //以创建写的形式打开目标文件
    int srcfd, destfd;  //记录源文件和目标文件的文件描述符
    if((srcfd = open(srcfile, O_RDONLY)) == -1)
    {
        perror("open srcfile error");
        return -1;
    }
    if((destfd = open(dstfile, O_WRONLY | O_CREAT | O_TRUNC, 0664)) == -1)
    {
        perror("open dstfile error");
        return -1;
    }
    //求源文件的大小
    int len = lseek(srcfd, 0, SEEK_END);
    //关闭文件描述符
    close(srcfd);
    close(destfd);
    //将源文件大小返回
    return len;
} 

//定义拷贝文件的函数
int copy_file(const char *srcfile, const char *dstfile, int start, int len)
{
    //以只读的形式打开源文件
    //以只写的形式打开目标文件
    int srcfd, destfd;  //记录源文件和目标文件的文件描述符
    if((srcfd = open(srcfile, O_RDONLY)) == -1)
    {
        perror("open srcfile error");
        return -1;
    }
    if((destfd = open(dstfile, O_WRONLY)) == -1)
    {
        perror("open dstfile error");
        close(srcfd);
        return -1;
    }
    //将两个文件的光标位置统一
    lseek(srcfd, start, SEEK_SET);
    lseek(destfd, start, SEEK_SET);
    //开始拷贝
    char buf[128] = "";  //数据的搬运工
    int sum = 0;
    while(1)
    {
        int res = read(srcfd, buf, sizeof(buf));
        if(res < 0)
        {
            perror("read error");
            break;
        }
        else if(res == 0)
        {
            break;
        }
        sum += res;
        if(sum > len)
        {
            write(destfd, buf, res - (sum - len));
            break;
        }
        write(destfd, buf, res);
    }
    close(srcfd);
    close(destfd);
    return 0;
}

int main(int argc, char *argv[])
{
    //使用外部传参，将要拷贝的文件以及存储文件传进来
    if(argc != 3)
    {
        printf("参数错误\n");
        return -1;
    }
    //获取源文件的长度，并且创建目标文件
    int len = get_file_size(argv[1], argv[2]);    
    pid_t pid = fork();
    if(pid > 0)
    {
        //父进程拷贝前一半的内容
        copy_file(argv[1], argv[2], 0, len/2);  //从开头位置拷贝，拷贝len/2内容
        //回收子进程资源
        wait(NULL);
    }
    else if(pid == 0)
    {
        //子进程拷贝后一半的内容
        copy_file(argv[1], argv[2], len/2, len - len/2);  //从len/2位置拷贝，拷贝剩余内容
        //退出进程
        exit(EXIT_SUCCESS);
    }
    printf("拷贝完成\n");
    return 0;
}
```

## 2.5 孤儿进程和僵尸进程

### 2.5.1孤儿进程
* **定义**：当前子进程还在运行，但它的**父进程已经提前退出**了。
* **说明**：每个进程退出后，其分配的系统资源（如 PCB 进程控制块）理应由其父进程进行回收。如果父进程先死了，子进程就会变成“孤儿”。
* **系统的兜底机制**：Linux 绝对不允许真正的“孤儿”存在。一旦进程变成孤儿进程，它会被系统的 **`1号进程`**（`init` 进程或现代系统的 `systemd`）强行收养。孤儿进程退出时的资源，将由它的新养父（1号进程）自动负责回收。因此，**孤儿进程是无害的**。

###  代码示例
```cpp
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>

int main() {
    pid_t pid = fork();

    if (pid < 0) {
        perror("fork error");
        return -1;
    } else if (pid > 0) {
        // 父进程：打印信息后立刻自杀，留下子进程
        printf("【父进程】我的 PID = %d. 我跑得快，我先退出了！\n", getpid());
        exit(0); 
    } else {
        // 子进程：故意休眠 2 秒，确保此时父进程已经死亡
        sleep(2);
        
        // 此时子进程已经变成了孤儿，被系统 1 号进程收养
        printf("【子进程】我的 PID = %d. 我刚醒来。\n", getpid());
        printf("【子进程】我去查一下我现在的父进程是谁？ PPID = %d\n", getppid());
        
        while(1); // 故意死循环，让你可以用 ps 命令查看它
    }
    return 0;
}
```
## 2.5.2 僵尸进程 (Zombie Process)
###  核心概念
* **定义**：当前子进程已经退出了，但是它的**父进程还没有为其回收资源**（没有调用 `wait`/`waitpid`）。
* **说明**：子进程死后，操作系统会自动回收它的内存和占用的文件描述符，但为了让父进程能查到子进程的“死因”（退出状态码），系统会刻意保留子进程的**进程控制块（PCB）和 PID 名额**。
* **危害分析**：僵尸进程已经是一个死掉的空壳，无法被 `kill -9` 杀死。如果父进程一直运行且一直不给子进程“收尸”，僵尸进程会越攒越多。操作系统的 PID 名额是有限的，最终会导致**系统无法再创建新进程**（内存泄漏/PID耗尽），这是极其严重的服务器 Bug。

### 代码示例
```cpp
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>

int main() {
    pid_t pid = fork();

    if (pid < 0) {
        perror("fork error");
        return -1;
    } else if (pid == 0) {
        // 子进程：打印信息后立刻自杀，变成一具尸体
        printf("【子进程】我的 PID = %d. 我执行完了，先走一步！\n", getpid());
        exit(0); 
    } else {
        // 父进程：故意进入超长休眠，就是不去调用 wait() 帮子进程收尸
        printf("【父进程】我的 PID = %d. 我正在呼呼大睡，不管儿子的死活...\n", getpid());
        
        // 父进程休眠的这 100 秒内，子进程就是一个绝对的【僵尸进程】
        sleep(100); 
    }
    return 0;
}
```
