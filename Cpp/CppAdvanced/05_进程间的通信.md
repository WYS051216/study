# 💻 Linux 进程间通信

## 0. 引入：为什么需要内核介入通信？
* **用户空间的隔离性**：由于多个进程的用户空间是相互独立的，其栈区、堆区、静态区的数据都是彼此私有的，因此**不可能直接通过用户空间**完成多个进程之间的数据通信。
* **外部文件的局限性**：虽然可以使用外部磁盘文件来完成数据传递（一个写，一个读），但这种方式必须保证写进程先执行、读进程后执行，需要复杂的同步机制来保证执行顺序，且磁盘 I/O 效率较低。
* **终极解决方案**：利用**内核空间**来完成通信。本质上是在内核空间创建一个特殊的区域（容器），一个进程向该区域存数据，另一个进程从该区域取数据。

---

## 1. 进程间通信 (IPC) 的基础概念
**IPC (InterProcess Communication)**：进程间通信。使用内核空间来完成多个进程间的相互通信。根据使用的容器或方式不同，主要分为以下三大类：

### IPC 机制分类
1. **内核提供的传统通信方式**
   * 有名管道 (Named Pipe)
   * 无名管道 (Anonymous Pipe)
   * 信号 (Signal)
2. **System Ⅴ 提供的通信方式**
   * 消息队列 (Message Queue)
   * 共享内存 (Shared Memory)
   * 信号量 (Semaphore)
3. **套接字通信 (Socket)**
   * 用于网络通信（支持跨主机进程间通信）

---

## 2. 无名管道 (Anonymous Pipe)

### 📝 核心原理与特性
1. **本质是特殊文件**：管道是一种特殊的文件，该文件**不用于持久化存储数据**，仅用于进程间的数据缓冲与通信。在 Linux 的 7 种文件类型 (`bcd-lsp`) 中，管道属于 `p` 类型。
   > **附 Linux 文件类型速记：**
   > * `b`: 块设备文件 (block)
   > * `c`: 字符设备文件 (character)
   > * `d`: 目录文件 (directory)
   > * `-`: 普通文件 (regular)
   > * `l`: 软链接文件 (link)
   > * `s`: 套接字文件 (socket)
   > * **`p`: 管道文件 (pipe)**
2. **存在于内存**：顾名思义，“无名”即不存在于可见的文件系统中，它直接在内存的内核空间中创建，**随着相关进程的结束而彻底消失**。
3. **血缘限制**：无名管道**仅适用于具有亲缘关系的进程间通信**（如父子进程、兄弟进程），不适用于非亲缘进程！

### 🛠️ 无名管道 API 函数
* **头文件**：`#include <unistd.h>`
* **函数原型**：`int pipe(int fildes[2]);`
* **功能**：在内核中创建一个无名管道，并返回该管道两端的文件描述符。
* **参数**：传入一个长度为 2 的整型数组。
  * **`fildes[0]`**：固定代表管道的**读端** (Read)
  * **`fildes[1]`**：固定代表管道的**写端** (Write)
* **返回值**：成功返回 0；失败返回 -1 并置位错误码。

---

### 💻 经典代码示例：父进程发送数据给子进程

> **⚠️ 核心避坑指南：**
> * 必须在 `fork()` **之前**调用 `pipe()` 创建管道。这样父子进程才能共享这同一个管道的两端描述符。
> * 单向通信原则：父进程写数据前，应关闭父进程的读端 `fildes[0]`；子进程读数据前，应关闭子进程的写端 `fildes[1]`。

```c
#include <sys/types.h>
#include <sys/wait.h>
#include <unistd.h>
#include <stdio.h>
#include <stdlib.h>
#include <fcntl.h>
#include <string.h>

int main(int argc, char *argv[])
{
    // 必须在此处（fork之前）创建管道文件。
    // 这样 fork 之后，父子进程都会完整继承该管道的两端文件描述符。
    int fildes[2];
    
    // 创建无名管道，并获取两端的文件描述符
    if(pipe(fildes) == -1)
    {
        perror("pipe error");
        return -1;
    }
    printf("fildes[0] (读端) = %d, fildes[1] (写端) = %d\n", fildes[0], fildes[1]);
    
    pid_t pid = fork();
    
    if(pid > 0)
    {
        // 1. 关闭不需要的读端
        close(fildes[0]);    
        char wbuf[128] = "hello world";
        // 2. 将数据通过写端写入管道
        write(fildes[1], wbuf, strlen(wbuf));
        // 3. 写完后关闭写端
        close(fildes[1]); 
        // 4. 阻塞等待回收子进程资源
        wait(NULL);
    }
    else if(pid == 0)
    {
        // 1. 关闭不需要的写端
        close(fildes[1]);
        char rbuf[128] = "";
        // 2. 从管道读端读取数据
        read(fildes[0], rbuf, sizeof(rbuf));
        printf("收到父进程的数据：%s\n", rbuf);
        // 3. 读完后关闭读端
        close(fildes[0]);
        // 4. 子进程退出
        exit(EXIT_SUCCESS);
    }
    else
    {
        perror("fork error");
        return -1;
    }
    return 0;
}
```

## 3. 管道通信的 6 大特点

**① 允许自我通信**
管道可以实现自己和自己发送消息（写端写入后，再由自己的读端读取）。
```c
#include <sys/types.h>
#include <sys/wait.h>
#include <unistd.h>
#include <stdio.h>
#include <stdlib.h>
#include <fcntl.h>
#include <string.h>

int main(int argc, char *argv[])
{
    int fildes[2];
    if(pipe(fildes) == -1)
    {
        perror("pipe");
        return -1;
    }
    printf("fildes[0]: %d, fildes[1]: %d\n", fildes[0], fildes[1]);
    
    // 定义两个容器
    char wbuf[128] = "hello world";
    char rbuf[128] = "";
    
    // 自己写，自己读
    write(fildes[1], wbuf, strlen(wbuf));
    read(fildes[0], rbuf, sizeof(rbuf));
    
    printf("rbuf: %s\n", rbuf);
    
    close(fildes[0]);
    close(fildes[1]);
    return 0;
}
```

**② 数据的“一次性”操作**
对管道中数据的操作是一次性的，当管道中的数据被读取后，就直接从管道中消失了，无法重复读取。

**③ 管道容量上限**
在绝大多数系统中，管道文件的大小限制是 **64K (65536 字节)**。

**④ 严格的先进先出 (FIFO)**
由于返回的是管道文件的文件描述符，所以对管道的操作只能是文件 IO 相关函数。**绝对不可以使用 `lseek` 对光标进行偏移**，必须严格做到先进先出。

**⑤ ⚠️ 核心考点：管道的读写阻塞特点**
* **写操作 (`write`) 的视角**：
  * **读端存在时**：写端有多少写多少。直到写满 64K 后，会在 `write` 处阻塞等待。
  * **读端不存在时**：写端再向管道中写入数据时，会发生**管道破裂 (Broken Pipe)**，内核空间会向用户空间发射一个 `SIGPIPE` 信号，进程收到该信号后会被强制退出。
* **读操作 (`read`) 的视角**：
  * **写端存在时**：读端有多少读多少。如果没有数据可读，会在 `read` 处阻塞等待。
  * **写端不存在时**：读端有多少读多少。如果没有数据了，**不会在 `read` 处阻塞**，而是直接返回 `0`（相当于读到文件末尾）。

**⑥ 通信模式：半双工通信**
管道通信在设计上属于半双工通信方式。
* **单工**：只能进程 A 向进程 B 发送消息（单行道）。
* **半双工**：同一时刻只能是 A 向 B 发消息，或者 B 向 A 发消息（对讲机模式）。
* **全双工**：任意时刻，A 和 B 都可以互相发送和接收通信（打电话模式）。

4.有名管道
顾名思义就是有名字的管道文件，会在文件系统中创建一个真实存在的管道文件
既可以完成亲缘进程间通信，也可以完成非亲缘进程间通信
有名管道的API
#include<sys/types.h>
#include<sts/stat.h>
int mkfifo(const char* pathname, mode_t *mode);
功能：创建一个管道文件，并存在于文件系统中
参数1：管道文件的名称
参数2：管道文件的权限
返回值：成功返回0，失败返回-1并置位错误码
注意：管道文件被创建后，其他进程就可以进行读写操作了，但是必须保证当前管道文件的两端都打开后，才能进行读写操作，否则函数会在open处阻塞
