## 原则一：编写清晰具体的指令
**不要让模型去猜你的心思。** 指令越模糊，AI 越容易“放飞自我”。你需要明确告诉它：你要什么格式、多长、什么语气、甚至是给谁看的。
* ❌ **反面案例**：“给我写个请假条。”（AI 不知道你为什么请假、向谁请假、语气是严肃还是委婉）
* ✅ **正面案例**：“你是一个有 5 年工作经验的互联网打工人。请帮我写一封给项目经理的请假邮件，说明我明天需要去医院拔智齿，请求休假一天，并说明手头的工作已经交接给同事小王。语气要诚恳、专业，字数控制在 100 字左右。”

## 原则二：提供参考文本
**防止 AI“一本正经地胡说八道”（幻觉）。** 大模型虽然读过很多书，但它可能记混。如果你有现成的资料，直接喂给它，让它基于你的资料来回答。
* 💡 **技巧**：使用引号 `"""` 或 XML 标签 `<text>` 把参考资料包裹起来，告诉 AI “只从这段材料里找答案”。
* ✅ **正面案例**：“请根据以下三个引号内的文本，总结出这款手机的 3 个核心卖点。如果文本中没有提到卖点，请回答‘未提及’。
  \"\"\" 
  （这里粘贴你的产品说明书原文）
  \"\"\" ”

## 原则三：拆分复杂任务
**不要试图“一口吃成个胖子”。** 面对复杂的巨型任务，大模型的出错率会急剧上升。把大任务拆解成一系列小步骤，像流水线一样一步步指导它。
* ❌ **反面案例**：“帮我写一本 10 万字的科幻小说。”
* ✅ **正面案例**：
  * 第一步：“请帮我想 5 个关于‘火星生存’的科幻小说点子。”
  * 第二步：“我选第 3 个点子，请基于它帮我写一个包含 10 章的目录。”
  * 第三步：“请根据目录，帮我写第一章的第一节，重点刻画主角的心理活动。”

## 原则四：给模型时间去思考
**强迫 AI 在给出最终答案前，先“打草稿”。** AI 很多时候答错，是因为它急于给出最终结论。你可以通过指令强制它展示推理过程。
* 💡 **技巧**：在提示词结尾加上**“请一步步思考（Let's think step by step）”**，或者要求它“在给出最终结论前，先列出推理过程”。
* ✅ **正面案例**：“小明有 5 个苹果，给了小红 2 个，又买回了原本剩下数量的两倍。小明现在有几个？**请在给出最终数字前，写出你每一步的计算过程。**”

## 原则五：使用外部工具
**认清大模型的弱点，善用“外挂”。** 大模型本质上是文字接龙的概率游戏，它有天生的缺陷：
1. **不会精确计算**（复杂的数学运算容易算错）。
2. **没有实时信息**（如果它的训练数据只到 2023 年，它就不知道今天的新闻）。
3. **记不住海量数据**（受限于上下文窗口大小，喂给它一本十万字的字典它可能会忘掉开头）。
* 💡 **对策（工具调用模板）**：给 AI 接入计算器、联网搜索插件、或者本地知识库（RAG）。
* ✅ **正面案例**：“请**调用你的[联网搜索工具]**，查询今天上证指数的收盘点位，并**调用[Python代码工具]**计算它与昨天相比涨跌了百分之几。”

## 原则六：系统性测试更改
**像做科学实验一样去优化你的提示词。** 
* 🔬 **控制单一变量**：当你发现 AI 的回答不令人满意时，**不要一次性把提示词全部重写**。
* 💡 **正确做法**：如果输出不够好，先试着只修改“角色设定”，看看效果；如果还不行，再单独修改“输出格式”。一次只改一个地方，你才能知道到底哪一句话是真正起作用的。

## 7. 提示词的基本结构

一个完整的高质量提示词通常包含以下五个基本结构：

* **角色 (Role)**：给大模型定身份。
  * **作用与好处**：设定“边界”，锁定特定的专业视角，从而激活模型在该领域的专业知识。
* **任务 (Task)**：给大模型定目标。
  * **作用与好处**：明确最终目标，帮助模型拆解复杂的任务。
* **技能 (Skill)**：给大模型定能力。
  * **作用与好处**：指定所需的专业能力，防止模型在不同能力之间产生混乱或叠加。
* **输出格式 (Format)**：给大模型定规范。
  * **作用与好处**：明确交付格式的定义，指定技术要求与内容排版规范。
* **条件与限制 (Constraints)**：给大模型定边界。
  * **作用与好处**：防止模型思维跑偏，有效控制输出风险。

## 8. 提示词框架

* **什么是提示词框架**：一套结构化、模板化的提示词写作模板与方法论。
* **目的**：将脑海中的想法转化为一步一步的具体要求。
* **底层本质**：人与大语言模型之间的一种高效沟通协议。

### 8.1 通用万能型框架
* **RTF 框架**: 角色 (Role) + 任务 (Task) + 格式 (Format)。
* **ICIO 框架**: 
  * **指令 (Instruction)**：锚定核心目标，以动词作为明确的行动起点。
  * **上下文 (Context)**：对齐执行语境，明确用途、风格与受众。即让 AI 理解“为什么这样做”，从而生成切合具体业务场景的个性化、高相关性内容。
  * **输入数据 (Input Data)**：提供任务的载体，交付完整的核心原始内容。
  * **输出指引 (Output Indicator)**：定义交付结果，规范输出的格式、结构与标准。
* **CO-STAR 框架**: 背景 (Context) + 目标 (Objective) + 风格 (Style) + 语调 (Tone) + 受众 (Audience) + 输出格式 (Response)。
* **CRISPE 框架**: 背景 (Context) + 角色 (Role) + 指令 (Instruction) + 风格 (Style) + 语气 (Tone) + 输出格式 (Format)。

### 8.2 推理逻辑型框架
* **CoT (Chain of Thought / 思维链)**:
  * **核心思想**：过程显性化（强迫模型一步步展示思考过程）。
* **ToT (Tree of Thoughts / 思维树)**:
  * **核心思想**：树状搜索的迭代进化。
  * **关键流程**：01 多元生成 ➔ 02 价值剪枝 ➔ 03 迭代推导。
* **ReAct 框架 (Reason + Act)**:
  * **核心思想**：打破大模型内部推理的黑盒模式，将“逻辑思考”与“外部行动”同步显性化。
  * **标准流程**：遵循 **思考 (Thought) ➔ 行动 (Action) ➔ 观察 (Observation)** 的动态闭环。
  * **适用场景**：需要调用外部工具，或涉及多步骤拆解的复杂任务。

### 8.3 创作营销型框架
* **AIDA 营销框架**：常用于激发兴趣和促成转化（Attention 注意 ➔ Interest 兴趣 ➔ Desire 欲望 ➔ Action 行动）。
* **PAS 痛点框架**：常用于文案写作（Problem 提出问题 ➔ Agitation 加剧痛点 ➔ Solution 给出方案）。

### 8.4 项目规划型框架
* **BROKE 框架**: 背景 (Background) + 角色 (Role) + 目标 (Objective) + 关键结果 (Key Results) + 进化 (Evolve)。

## 9. 提示词进阶技术 (Advanced Prompting Techniques)

### 9.1 样本提示技术 (Sample-based Prompting)
* **零样本提示 (Zero-Shot Prompting)**
  * **定义**：在不提供任何参考示例的前提下，直接向大模型下达任务。
* **单样本提示 (One-Shot Prompting)**
  * **定义**：在下达指令时，只给大模型提供一个参考示例。
* **少样本提示 (Few-Shot Prompting)**
  * **定义**：在下达命令之前，给大模型看几个高质量的任务示例。
  * **核心价值**：让输出的格式更加可控，整体风格更加统一。

### 9.2 推理与思维链技术 (Reasoning & Chain of Thought)
* **思维链提示 (Chain of Thought, CoT)**
  * **核心思想**：分步思考，拒绝跳跃。
  * **核心作用**：激活大模型的复杂逻辑推理能力。
* **零样本思维链 (Zero-Shot CoT)**
  * **核心思想**：指令即引导（例如只需在句末加上“请一步步思考”）。
  * **关键作用**：降低编写门槛，同时提升模型的推理效能。
* **自洽思维链 (Self-Consistency CoT)**
  * **核心运作机制**：让模型基于不同的初始条件或逻辑起点，生成多条独立的思维链，最终通过投票或比对得出结论。
  * **效能提升逻辑**：有效解决复杂问题中“一次算错，全盘皆错”的痛点。

### 9.3 约束与控制技术 (Constraints & Formatting)
* **格式强制提示 (Format Forcing)**
  * **核心思想**：提供无歧义的结构化指令。
  * **关键作用**：起到规范约束与提升解析效能的双重作用。
* **约束提示 (Constraint Prompting)**
  * **核心思想**：为 AI 立规矩（例如限制字数、禁用词汇、指定语气）。
  * **关键作用**：严格控制 AI 的行为边界。

### 9.4 互动与执行策略 (Interaction & Execution)
* **复述确认 (Reframing/Confirmation)**
  * **核心思想**：建立共同认知基准（让 AI 先复述一遍它理解的任务）。
  * **关键作用**：规避执行偏差风险，确保指令被准确理解。
* **自我修正 (Self-Refine)**
  * **核心思想**：赋予 AI 自我审视的元能力，让其在输出最终结果前，先对初稿进行检查和优化。
* **多轮拆解 (Multi-turn Decomposition)**
  * **核心思想**：化整为零，分步执行。
  * **核心价值**：降维化解复杂任务的难度，大幅提升最终输出质量。

### 9.5 高阶复杂思考架构 (Advanced Architectures)
* **树状思考 (Tree of Thoughts, ToT)**
  * **核心思想**：从发散探索到收敛决策，评估多种可能的分支路径。
* **图思考 (Graph of Thoughts, GoT)**
  * **核心思想**：将问题里的关键信息抽象成一个个“节点”，并通过逻辑将它们建立“关系”，形成网状图结构的思考模式。
* **检索增强生成 (RAG, Retrieval-Augmented Generation)**
  * **核心思想**：检索先行，生成在后（先找资料，再基于资料回答）。
  * **核心价值**：解决大模型幻觉与信息滞后问题，是企业级应用落地的关键解法。

## 10. 提示词自动化

* **什么是提示词自动化**：指利用人工智能（AI 自身）自动完成提示词从**生成、优化、选择到持续迭代**的全生命周期管理过程。简而言之，就是让 AI 帮我们写提示词。
* **核心目标**：摆脱对个人“语感”和经验的依赖，让优质的 AI 交互策略从“玄学”变成标准化、可复制、可扩展的工程能力。

---

## 自动化流程总览 (四大核心步骤)

### 步骤一：制作元提示模板 (Meta-Prompt)
* **核心思想**：创建一个专门用来指导 AI 生成高质量提示词的“母提示词”（即 Prompt for Prompt）。
* **模板要素**：
  1. **定义角色**：首先定义清晰的角色（例如：“你是一个资深的提示词工程架构师”）。
  2. **任务目标**：其次明确具体的任务目标（例如：“帮我生成一个用于小红书爆款文案的提示词”）。
  3. **执行逻辑**：接着是分步的执行逻辑（指导 AI 如何一步步思考、拆解业务需求）。
  4. **输出格式**：最后是标准化的输出格式（例如要求输出特定的 Markdown 结构或 JSON 格式）。
* **关键指令**：指令 AI 在生成时必须采用结构化的表达方式，强制加入推导过程，并且设定严格的内容与格式约束。

### 步骤二：批量生成提示词变体 (Batch Generation)
* **核心目标**：基于元模板的框架，让 AI 发散思维，自动生成 10-20 个甚至更多不同侧重点的候选提示词。
* **关键变量维度**：对提示词进行多维度的差异化微调。例如：改变角色设定（严谨专家 vs 幽默博主）、调整长度、使用不同的提示词框架（如 CoT 思维链 vs 零样本）。
* **效能提升优势**：极大拓宽了探索边界，有效避免了人类编写单一提示词时的思维局限性，实现“大力出奇迹”。

### 步骤三：自动评估打分 (Auto-Evaluation)
* **多维评估体系**：建立严谨的量化评分模型。比如从“准确性”、“任务相关性”、“格式合规性”、“创新性”等多个维度设定权重进行打分。
* **AI 专家评审 (LLM-as-a-Judge)**：引入另一个更强大的大模型（如 GPT-4 / Claude 3.5 Opus）作为“冷酷的裁判”，让它根据评估标准对批量生成的候选结果进行自动化阅卷。
* **优选高效决策**：根据得分排名，自动筛选出表现最好的前几个（Top-K）提示词进入下一轮的迭代。

### 步骤四：自动迭代优化 (Auto-Iteration)
* **优化对象**：在评估环节中得分不高、出现具体错误（如格式不合规、出现幻觉）的候选提示词，以及虽然得分最高但仍有提升空间的“准冠军”提示词。
* **优化方向**：
  1. **查漏补缺**：根据裁判 AI 的反馈，自动增加更严格的约束条件（如“必须限制在500字内”或“禁止使用某些词汇”）。
  2. **强化上下文**：补充能帮助 AI 理解背景的关键信息。
  3. **动态少样本 (Dynamic Few-Shot)**：自动从历史的高分回答中提取优秀案例，作为示例（Examples）塞进提示词中，供下一代 AI 参考。
* **最终产出**：经过多轮“生成 ➔ 打分 ➔ 优化”的自动化闭环后，最终交付一个**抗压能力强、表现极其稳定、可直接投入生产环境**的“黄金提示词”。

## 11. 提示词工程化核心技术 (代码接入必备)
* **模板化与变量占位符 (Templating & Placeholders)**
  * 用法：把 Prompt 写成包含 `{变量}` 的模板结构，运行时动态注入数据。
  * 价值：告别一次性话术，实现自动化批量处理。
* **分隔符防注入 (Delimiters)**
  * 用法：用 `###`、`"""` 等符号将“系统指令”与“用户输入数据”进行物理隔离。
  * 价值：防范提示词注入攻击，剥夺用户输入的指令执行权限。
* **兜底指令降幻觉 (Fallback Instructions)**
  * 用法：在末尾增加强约束指令（如“信息不足就回答不知道，绝不编造”）。
  * 价值：抑制大模型的发散联想与表现欲，保证输出的严谨性与安全性。

## 调用大模型 API

  ### 1. 环境准备
  ```bash
  pip install openai
  ```

  ### 2. 基础调用（OpenAI 兼容格式，DeepSeek 为例）
  ```python
  from openai import OpenAI

  client = OpenAI(
      api_key="你的密钥",
      base_url="https://api.deepseek.com",
  )

  resp = client.chat.completions.create(
      model="deepseek-chat",
      messages=[{"role": "user", "content": "你好"}],
  )
  print(resp.choices[0].message.content)
  ```

  ### 3. 带「模板化 + 分隔符」的调用
  ```python
  def translate(text, language):
      prompt = f"把 ###{text}### 翻译成 {language}，只输出翻译结果，不要解释"
      resp = client.chat.completions.create(
          model="deepseek-chat",
          messages=[{"role": "user", "content": prompt}],
      )
      return resp.choices[0].message.content
  ```

  ### 4. 多轮对话（无状态 + messages 列表）
  ```python
  messages = [{"role": "system", "content": "你是一个简洁的助手"}]

  while True:
      user_input = input("你：")
      if user_input in ("退出", "quit", "exit"):
          break

      # 把用户的话加进历史
      messages.append({"role": "user", "content": user_input})

      # 把【完整历史】发给模型
      resp = client.chat.completions.create(
          model="deepseek-chat",
          messages=messages,
      )
      reply = resp.choices[0].message.content
      print("AI：", reply)

      # 把模型的回复也加进历史（下一轮它才「记得」）
      messages.append({"role": "assistant", "content": reply})
  ```

  ### 5. 流式输出（打字机效果）
  ```python
  resp = client.chat.completions.create(
      model="deepseek-chat",
      messages=messages,
      stream=True,   # 关键：开流式
  )
  for chunk in resp:
      delta = chunk.choices[0].delta.content
      if delta:
          print(delta, end="", flush=True)
  print()  # 结尾换行
  ```
